## 9. Push result
**VERIFIED (via API publication — see method note).** A literal `git push` was attempted first and **failed**: GitHub answered `Invalid username or token` because this connection's credential is exchanged only for requests to `api.github.com` (the registered host); the git transport endpoint (`github.com`) never receives the real token, and the token was not — and must never be — extracted to work around that. Two further constraints were proven empirically:
- The Git Data API refuses blob creation on a completely empty repository (409), so the repository was bootstrapped with one Contents-API commit (README).
- With this fine-grained token, the Git Data API tree/commit endpoints return 403/404 (`Resource not accessible by personal access token`) — single-tree/single-commit publication is not available to this token.
Publication was therefore completed through the Contents API (the same sanctioned route used for the owner's other repositories): one commit per file on `main`, every commit carrying the message `stage-01: professional application foundation`. No force push was used at any point; no remote history existed to overwrite (the repository was verified empty beforehand, §10).
