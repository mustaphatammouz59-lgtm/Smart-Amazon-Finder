## 3. Final application architecture

Modular monolith exactly as Stage 00 specifies: one Worker serves the SSR application and API routes; React Router loaders/actions are the server layer; bindings DB (D1), APP_KV (KV), MEDIA (R2), JOBS (Queues) are declared and typed end-to-end. The brand placeholder is isolated in `app/config/site.ts` (+ `SITE_URL` var): changing the working name to the final brand is a two-file config change. Foundation pages carry honest content about how each tool will work — no placeholder products, prices or reviews exist anywhere. Foundation/noindex policy is enforced three ways: per-page `noindex` meta on legal pages, `robots.txt` disallow-all during foundation, and an `X-Robots-Tag: noindex, nofollow` header from the Worker — all three flip in one documented change at public launch (Stage 11).

## 12. Known issues

- **K-1 (environment, resolved):** the first template scaffold attempt targeted `/tmp`, which is a 512 MB tmpfs in this VM and filled during install (ENOSPC on the workerd binary). Scaffold was redone under `~/workspace` (136 GB free). No project impact.
- **K-2 (fixed during build):** the first `entry.server.tsx` used `renderToPipeableStream`, which does not exist in the Workers (edge) build of `react-dom/server` — pages returned 500 in the runtime despite a clean typecheck/build. Rewritten to `renderToReadableStream`; all routes then verified 200. Lesson recorded: for this stack, a green build is not runtime proof — the workerd route sweep is a mandatory stage gate (it is what caught this).
- **K-3 (note):** React Router emits a "Future Flag Warning" about v8 trailing-slash data-request formats in dev/preview logs. Informational only; no behaviour impact in v7.
- **K-4 (dependency note):** `npm install` with vitest 4.x failed inside npm's own peer resolver (arborist `edgesOut` error) in this environment; vitest is pinned to the current v3 line (3.2.7), which installs cleanly and covers the Stage 01 test scope. Revisit when the resolver issue clears.
- **K-5 (verification gap):** `npm audit` cannot run in this VM (registry policy). See §8. CI workflow runs the standard checks; add an audit step there when the repo is connected.
- **K-6 (by design):** local D1/KV/R2/Queues state is emulated; production binding behaviour (quotas, latency) is only provable at the deployment stage. Queue consumer is a foundation ack-and-log stub, per the architecture.
- **K-7 (by design):** canonical/OG URLs use the placeholder `workers.dev` base from `siteConfig` until the Stage 11 domain decision.
